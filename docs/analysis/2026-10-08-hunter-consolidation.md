# 趋势猎手版本合并

V1–V4是同一趋势策略系列的迭代，不是四套独立策略，也不是仅修改参数的完全相同算法。

| 版本 | 入场与管理变化 |
| --- | --- |
| V1 | 多周期趋势、相对强弱、突破回踩确认；分批止盈 |
| V2 | 沿用V1，增加EMA20趋势回调，调整排名、量能和有效期 |
| V3 | 沿用前序入口，增加短线趋势延续、重要阻力筛选和BTC横盘机会 |
| V4 | 短线调用V3入口，中长线沿用V2并增加延续；新增方向质量、结构止损缓冲、成本后目标、全仓波段持有和确认反转退出 |

依据：`src/lib/hunter/rules.ts`、`adaptive.ts`、`swing.ts`及服务器对应实现。反弹猎手是独立的均值回归策略，保留。

## 保留选择

保留工程上最完整的趋势猎手V4，撤下V1–V3的创建和升级选项。不能据此宣称V4盈利能力已经最好。

已有开发样本仅24小时、短线、同一快照；V4过滤参数使用过该样本，不能算独立样本外检验。V1没有可比完整收益检验；V2主要有发现频率证据。

| 同样本结果 | V3 | V4修正版 |
| --- | ---: | ---: |
| 已完成交易 | 26 | 21 |
| 已平仓净收益（USDT） | -12.60 | -4.16 |
| 利润因子 | 0.617 | 0.775 |
| 最大回撤 | 2.10% | 1.03% |
| 期末含浮动净值（初始1000） | 996.38 | 995.32 |

V4已平仓亏损和回撤较小，但期末含浮动净值略低于V3；两者仍亏损，没有可靠的盈利优胜者。保留V4依据是功能覆盖和风险管理完整度。

证据：`docs/plans/2026-10-04-hunter-swing-filtered-evidence.json`。实际计划净3:1并非已实现收益。

## 兼容处理

- 新建默认V4，服务器能力仅公布V4和反弹猎手；旧客户端新建V1–V3返回410并提示更新。
- 读取运行/暂停的旧猎手或领取服务器扫描任务时，将后续扫描配置合并至V4；清除旧扫描租约、重建统计。配置指纹防止旧扫描挂载。
- 资金、杠杆、币池、周期、方向、模型、名单、锁利和暂停状态保留。已停止/正在退出的历史组不改写。
- 已挂载机会的计划和子任务保持冻结，包含尚未成交的原有计划；旧持仓继续按原版本减仓和退出。旧算法只用于历史兼容、冻结管理和V4共享的底层入口。
- 旧客户端的均衡版/机会增强版升级请求统一指向V4，不能恢复已撤下版本。

验证：桌面类型检查、构建、全量835项通过、1项已有跳过（策略模块91项）；隔离界面仅显示两项、默认和提交V4、切换反弹后独立周期正确。服务器相关207项通过、1项已有跳过，包含创建拦截、迁移保留配置、旧仓位分批退出、托管租约失效、旧升级入口与反弹回归。
