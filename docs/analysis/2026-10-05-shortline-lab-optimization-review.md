# 短线因子实验室自查与优化评审

日期：2026-10-05，北京时间。本文保留改造前的自查证据；已落实的第一阶段改造和待完成的独立验证见 [实施说明](2026-10-05-shortline-lab-upgrade.md)。未改写运行中任务的冻结参数。

## 1. “15周期短线”的实际问题

定位到 admin 的 ADAUSDT 任务“15周期短线”，strategy_type=shortline_factor，15m，100U 单笔保证金、10倍杠杆。任务当前配置：组合分阈值0.25，连续3步确认，每小时最多6次动作，每根K线最多1次动作；兜底止损5%、止盈20%，自动锁利、冷却1次。载荷为一个因子、权重1。

以服务器已成交订单账本按数量配对重建闭合交易轮次，排除尚未平仓部分，2026-10-03至检查时的结果如下。净额扣开平仓手续费，未纳入资金费；并非逐笔重新向交易所独立审计后的完整净账单。期间规则可能变更，12轮样本不足以估计长期表现。

| 指标 | 观察值 |
| --- | ---: |
| 已完成轮次 | 12 |
| 净盈利 / 净亏损轮次 | 4 / 8 |
| 扣手续费后胜率 | 33.33% |
| 平均净盈利 | 3.2105U |
| 平均净亏损绝对值 | 4.9498U |
| 实际平均盈亏比 | 0.649:1 |
| 毛已实现盈亏 | -15.5096U |
| 开平仓手续费 | 11.2465U |
| 扣手续费后盈亏，资金费之前 | -26.7561U |
| Profit Factor：累计净盈利 / 累计净亏损绝对值 | 0.3243 |

部分毛盈利被成本吞掉：毛赚0.134U，扣费净亏0.8459U；毛赚0.0568U，扣费净亏0.9200U。日志显示多笔因“连续3步回中性带”离场，需用同样退出规则回放验证，不能仅依据因子方向相关性判断盈利。

止损执行也存在待查问题。日志曾记录“止损5%”但首次可见触发读数约为-10.00%及-7.27%，对应交易最终净亏约11.39U、8.19U。另有平仓失败“无持仓可平”，随后再次关闭的记录。这证明需要检查触发与成交延迟、仓位上账延迟及行情时效，尚不能仅凭这些日志归因某一个故障。市价成交和跳价仍可能越过止损线，原生条件单也不能保证精确成交在止损价。

## 2. 已查证的挖掘与执行偏差

### 2.1 研究仓位不等于短线执行仓位

`public/pykernel/factor_lab/scoring/evaluate.py` 默认以 tanh 因子形成连续仓位，收益为仓位乘下一根收益、减换手成本。短线运行时采用固定名义额度、0.25阈值、3步确认、中性或反向确认退出、每根K线最多一次仓位变化，叠加兜底与锁利。

当前实验室V2创建请求未指定执行模型和实盘离散门；搜索配置默认 execution_model=signal_research、live_entry_gate=0。已有的一般离散报告也不是完整的15秒短线状态机。`src/lib/shortline/replay.ts` 和 `gate.ts` 存在形成中K线重放及稳定性/IC检验，但实验室V2主流程没有调用该门。挂载时的黄金夹具验证数值一致性，不等同于真实开平仓盈亏检验。

结论：封存通过只证明当前研究评估口径通过，不能证明部署后的短线状态机有正净收益。这是最优先的挖掘改造。

### 2.2 研究市场和执行市场不同

实验室V2硬编码 data_channel=binance_usdt，逐笔归档来自 Binance Vision；服务器短线feed实际是OKX永续公共成交。价格、交易量和主动成交分布不同，订单流因子的跨所表现需专门验证。

优化方向：OKX服务器转发与持续采集作为可部署数据源；Binance数据继续用于辅助研究、扩展市场状态，但不能直接把其验收结论标为OKX执行通过。历史订单流不足时明确样本缺口，不用OHLCV伪造逐笔成交。

### 2.3 成本假设偏乐观

界面默认 cost=0.0003，为每单位换手成本0.03%。账本中约1000U名义的一轮开平仓费用常接近1U，部分市价成交对应单边0.05%。实际费率应以绑定账户和合约为准，不把统一公开费率当作所有用户的费率。

优化方向：从服务器获取该账户Maker/Taker费率；回放区分挂单、吃单、撤补单，分别扣开仓费、平仓费、买卖价差、滑点和已发生的资金费。成本压力测试增加的是成交摩擦；资金费保留其现金流符号与时间，不机械把收入也乘2。

### 2.4 快速信号的搜索目标可能不合周期

短线适应度沿用半衰期48根、翻转率和换手惩罚。48根在1m是48分钟，在15m是12小时。它可能使15m搜索更偏向长时间同向的表达式，这是由评分公式推导的待验证假设，尚未做改动前后实验。

不能直接移除换手惩罚。应在新研究版本中把信号稳定时间与预测/持仓跨度对齐，并以扣费后的事件交易盈亏重新排名。原来的CPU/GPU冻结语义保持兼容。

### 2.5 1分钟挂载预热存在配置冲突

`requiredHistoryBars` 对1m的归一化窗至少1440，公式预热至少 1440+60+1+1440+10=2951根；服务器契约 WARMUP_MAX=2000。因此按当前页面计算的1m挂载载荷会超过服务器上限。15m不受此具体冲突影响。

应按公式需求、周期和资源预算分页拉取预热，校验完整历史深度，避免仅提高限制却仍只读取2000根，或静默截断历史。

### 2.6 研究级与执行级界限不足

实验室没有执行级冠军时，mountPool 会回退到 research_champions。界面提示其未过2倍成本压力，但这种选择不能提高任务的获利可靠性。不能认定当前ADA因子来自研究池，现有挂载快照不足以还原完整挖掘资格证据。

建议保留研究候选收藏/查看能力，新增清晰的执行验收证据；正式挂载必须显示币种、交易所、周期、执行规则、成本、样本区间和验收版本，并识别其是否与任务配置相同。改变现有研究级挂载权限属于后续产品决策，不能在本次自查中暗中撤销已有功能。

## 3. 推荐改造路线

### P0：降低执行偏差并建立可信净账单

1. 每轮记录实际成交数量、成交均价、开平仓费用、资金费、最大有利/不利波动、离场原因和触发到成交延迟。
2. 核对短线开仓后的原生止损保护。现有 `_place_live` 未传止损参数，短线亏损兜底主要由服务器轮询判断；拟通过已有live_trading边界按实际成交量设置任务归属的OKX原生保护，确认后再进入持仓管理。部分成交、未知ACK、停机恢复、触发竞态都须对账，避免重复开仓或误平其他任务。
3. 亏损退出应走明确的紧急成交策略，不受正常交易频率限制；当前只有锁利退出显式传force_market，须验证兜底止损是否仍可能进入限价等待/撤补链。
4. 止损后等待新的有效信号，持久化信号身份，避免同一个已消费信号在新K线或服务重启后立刻重复进场。不能通过删掉历史或重置盈利统计隐藏亏损。

### P1：两阶段搜索，最终以真实短线状态机验收

第一阶段由CPU/GPU快速发现方向预测候选，增加多种随机种子、简单可解释模板、行为去重及受控的停滞重启。优先搜索服务器具备数据源的特征，单列研究用订单流候选池，减少最终不可挂载的无效搜索。

第二阶段对训练/验证中留下的有限候选重放形成中K线。复用真实短线阈值、确认次数、限频、开平仓、部分成交、止损、锁利与冷却语义，不能另写一个假设立即成交的简化回测。先验证CPU、原生GPU与服务器在同一冻结输入上的信号/订单意图一致，再对模型化成交成本作压力测试。

排名主体改为扣费净期望、净Profit Factor、实际平均盈亏比和回撤。IC、Sortino、稳定性仍保留，用于筛选方向质量与稳健性；不能把IC或逐步收益为正直接解释为“胜率高”。

### P2：提高有效候选数量与跨状态适应性

- 分别探索趋势延续、顺势回撤、波动突破、区间均值回归的简单模板，按验证阶段确定环境适配，避免无区别地混为一类。
- 对单因子和少量低相关因子组合都作独立验证。现有组合代码可以复用，但V2页面创建请求未开启combo_super；组合通过不代表每个成员都通过，任务必须挂载验收过的那个组合及冻结权重。
- 候选池保留边界明确的研究候选，不因为一次训练段表现差就完全丢掉搜索多样性；上线质量门保持严格，不以降低样本外或成本要求凑冠军数量。
- 展示失败原因计数：样本不足、缺失特征、样本外亏损、某折失败、成本压力失败、重放失败、缺少服务器数据源。没有用户近期本地挖掘的拒因分布，当前不能确认是哪一关拒绝最多。
- 数据按日增量更新、校验覆盖和缺口。180天范围已经是当前默认，优化重点不是盲目延长，而是多状态覆盖与有效交易样本数量。

## 4. 盈利质量标准：建议验收目标，尚未验证能达到

设 p=扣全部费用后的胜率，W=平均净盈利，L=平均净亏损绝对值，则每轮净期望 E=pW-(1-p)L。平均盈亏比 R=W/L。

当前观察 R≈0.649，需要胜率约60.66%才收支平衡；仅提高到50%仍不够。若未来独立验证确实达到3:1，收支平衡胜率为25%；例如40%胜率对应+0.6R的平均期望。这是算术关系，不是对策略未来表现的预测。

推荐的初始验收要求：

| 项目 | 建议标准 |
| --- | --- |
| 净期望 | 验证段和封存段均为正，且不由少数异常大单撑起 |
| 净Profit Factor | 基准成本下≥1.3；加严成交摩擦后仍>1 |
| 平均净盈亏比 | 优先≥2:1，优化目标3:1；按实际闭合交易统计 |
| 胜率 | 与净盈亏比联合评价，不单独追求高胜率 |
| 交易样本 | 验证+封存优先100–200轮，封存至少50轮；少于此数明确为证据不足 |
| 风险 | 不加仓摊平亏损、不扩大已承担的止损；账户与任务资金限制始终有效 |
| 稳健性 | 时间切分、最大持仓跨度对应的purge/embargo、参数邻域、成本及延迟压力检验 |

不能把“止盈15%、止损5%”当作实盘3:1。锁利、提前退出、手续费及滑点都会改变实际W和L。入场机会的预期净目标收益也应扣完费用，再与预计止损净亏损比较。止损距离由波动/结构确定，按用户杠杆1–50倍和实际保证金约束反算数量，不因杠杆提高而放大单笔可承受损失。

持仓中分开使用入场阈值与退出阈值/确认时间，比较现有中性退出与迟滞退出、结构反转退出。所有参数只在训练/验证上选择，封存段只做最终验收；当前锁利模板必须纳入同样的回放，不能在回测中关闭它而部署时打开。手动止损、锁利、硬限制优先，研究改造不自动改写现有用户设置。

## 5. 实施与发布边界

建议以新的shortline研究/执行验收版本增加能力，旧公式、任务载荷、收藏、历史指标、CPU/GPU数值口径继续兼容。新增配置不自动热切正在交易的“15周期短线”。先用同数据同成本比较旧/新行为，再进行模拟盘影子验收；通过后才创建使用新验收版本的任务。

增加GPU代数只提高探索速度，不消除过拟合。候选数量增加时同时记录独立尝试规模，使用多重检验/DSR等信息评估选择偏差，封存样本不能被反复挖掘优化。
