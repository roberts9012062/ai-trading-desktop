# 非枢轴量化指标模拟审查（2026-10-05）

结论：发现了可复现的信号精度、开平仓冲突、回测/实盘窗口不一致等问题。现有回归测试通过，不代表这些场景没有缺陷。优先修复计算与执行口径，再讨论参数收益优化。

本次只增加审查脚本、行情夹具和证据，没有修改生产策略、运行中的任务、AI 提示词、风控或下单逻辑。桌面软件仍为 v0.2.111，服务器仍为 e246c627。没有发送交易指令。

## 范围与方法

排除 `swing_pivot`、`swing_pivot_v2`；覆盖其余 10 种：N 日突破、双均线、MACD、KDJ、布林波段、专业波段、强弱 V1、强弱 V2、因子公式、短线因子。专业波段虽然复用枢轴内核，仍按独立策略纳入检查。

- 9 种普通策略 × 7 类行情（横盘、上涨、下跌、周期震荡、交替噪声、跳变、随机游走）× 3 组参数 × 12 个数据长度 × 3 种方向模式 × 3 种持仓状态，共 **20,412 次评估**。小数持仓使用 0.005；这部分没有异常、非有限输出或违反方向限制的开仓。
- 额外检查低价缩放、150/300 周期、坏数据、特征缓存修订、前缀因果性、桌面 Python/服务端 Python 动作一致性、长周期收盘边界。
- **270 组成本回放**：10 组行情 × 9 种策略 × 3 档成本。每组每笔固定 1,000 报价币名义本金，初始资金 10,000，不加杠杆、不复利，收盘信号在下一根开盘执行；单边手续费加滑点为 0/5/10 bps。使用策略本身的出场及专业波段止损，没有叠加用户配置的止盈止损、资金费率、资金不足或交易所最小订单限制。结果用于暴露成本敏感性，不等同产品完整账户回测。
- BTC/ETH/SOL 各取本机 1 小时历史缓存末尾 850 根，共 2,550 根，主要覆盖 2026-08-21 至 2026-09-26；全部输入及 SHA256 已留档。缓存来自既有公开行情研究流程，本次没有重新向交易所核验这些缓存。历史回放仅覆盖约一个月，不能证明长期盈利。
- 短线独立引擎：3/5/10/15/30/60 秒六档，共 **16,200 个状态机步点（双跑）**；全部确定性一致，陈旧/NaN 分数没有产生动作。60 秒档在每 90 秒换方向的压力场景中没有完成三步确认，属于过滤效果。
- 短线已有真实 ETH aggTrades 测试消费 **1,444,908 笔成交**，尾部两小时 6,465 个秒桶，3/5/15/60 秒重放各 2,380/1,428/476/119 步，双跑指纹一致；桌面与服务器短线 v2 评分一致性通过。

## 跨策略问题与证据

### 1. 图表精度与服务器计算不一致

服务器 `backend/app/services/ai/tools/calc.py` 的 SMA（25/28 行）、MACD（82–84 行）、布林（147–149 行）固定四位小数；桌面图表 `src/lib/indicators.ts` 使用有效数字。固定四位小数在低价币上抹掉数值，可能出现“图表看到交叉，任务没有信号”或布林误触发。

缩放实验是同一根价格路径乘以 1e-7，不改变百分比走势；因此上述差异是计算精度缺陷，不是币种盈利能力差异。普通 SMA、MACD、布林都需两端/出场标准一起对齐，不能仅修改图表。

### 2. 历史回测、合成回放与实盘窗口不同

`backend/app/services/backtest/runner.py:175` 默认 120 根；`backend/app/services/backtest/synthetic.py:697` 也取 120 根；`backend/app/services/ai_trading/engine.py:561` 拉 240 根并在 877 行截取。专业波段有独立倍率扩展，不能简单套统一常数。

合法 150 周期的均线/突破/MACD/布林在 120 根时都返回 `insufficient_data`，240 根可形成；300 周期的突破/慢均线在实盘 240 根也无法形成。因子 VM v3 输出窗口为 250，特征层还有嵌套窗口；“统一改成 240”仍不足以保证所有公式完全预热。

建议用策略参数/公式依赖计算最小预热与稳定预热，取数不够时明确阻止启动或报告不足；每个信号使用同一套窗口和归一化版本。在纯因子专项中，固定 normalization_window=200 的已有有限特征前缀差为 0；默认随整段推导窗口的前缀差最高 1.618847。缺少衍生输入的 v3 特征用 NaN 标记是既有缺失语义，本报告没有将这种标记本身列为缺陷。

### 3. 桌面旧 Python 内核需要单独管理

`public/pykernel/strategies` 不支持专业波段、强弱 V1/V2，未知类型返回 `hold`。它的仓位读取仍含 `int()`，把 0.005 截为 0。在 102 次/策略同数据对比中，动作差异为：MA 2、突破 28、MACD 0、KDJ 8、布林 39、因子 60。

**当前桌面历史回测页面通过 `runBacktestApi` 走服务器**，因此不能据此声称当前页面全部回测都被这个旧内核影响。风险集中于仍调用 `runBacktestLocal` 的入口、未来恢复本地模式、其他内核消费者。建议支持矩阵显式校验，未知类型直接报错，统一小数数量，不再静默返回成功的零交易结果。本轮 Python 两端对照在 CPython 加载源码，未声称完成 Pyodide/WASM 浮点资格认证。

### 4. 异常行情保护不足

把最后一根 close 改为 0/缺字段/非法字符串，突破会开空，布林会开多；部分强弱/因子路径直接抛异常，NaN 还可能进入快照。`kline_crypto.py` 的行转换未见统一有限性/价格区间验证。

这些是**直接注入坏数据的防御性模拟**，不代表生产交易所正在发送坏行情。应在任务计算入口统一验证时间、OHLC 关系、正价格、有限数值及成交量；不能把非法价格当 0 继续产生交易信号。缺少 funding/OI 等可选输入则按既有缺失规则处理，不能误拒绝全部普通策略。
