# SOL 2024-04 官方归档成交量异常及修复

> 后续修正：v0.2.176 的官方域名直连不适用于用户桌面网络。v0.2.177 已改用现有 Snippets REST 线路池，分页上限改为代理允许的 100 根。见 [Snippets 路由修正与验证](okx-sol-snippets-repair-2026-10-11.md)。下文保留当时的数据诊断及直连方案记录。

用户报告：`OKX 官方历史文件校验失败（2024-04）：OKX 合约数量换算不一致；不会转发服务器`。

## 根因和独立证据

下载 OKX 官方 `SOL-USDT-SWAP-candlesticks-2024-04.zip`，共 43,200 根分钟线。其中 17,725 根 `vol_ccy` 与官方历史 API 的 SOL 成交量不同。2024-04-11、2024-04-12 日包也存在同样问题，改用日包不能解决。

例如北京时间 2024-04-11 22:24：归档的合约数量为 2253.3、SOL 成交量为 2252，API 则为 2253.3 SOL；下一分钟分别是 911.6、905 和 911.6 SOL。这不是浮点精度误差。原文件 SHA-256：`00d48a1128ddcf217277425711c2448a01cc9bf248f977beb2cf74cfcc6c3fa5`。

通过官方 `app.okx.com/api/v5/market/history-candles` 分 144 页下载全月分钟数据；`www.okx.com` 同样能返回抽样的正确数据。全月价格 OHLC、合约数量及成交额与归档逐分钟一致，差异在基础币成交量字段。字段语义及分页规则见 [OKX 官方 API 文档](https://www.okx.com/docs-v5/en/#order-book-trading-market-data-get-candlesticks-history)。

此前挖掘验证的是 2026 年近期数据及另一条日线数据路径，不能据此推断所有历史月包均正确。本次确认了 2024-04 官方归档的数据质量问题。

## 桌面端 v0.2.176 行为

- 严格解析器和合约面值容差保持不变。只有发现合约数量换算不一致时，才启动官方 API 交叉校验。
- 本机直接请求 OKX 官方公共分钟 API，不携带用户凭据，不经业务服务器。分页有超时、取消、限速和单调时间检查，加载界面显示校验进度。
- 对归档中每根分钟线核对 OHLC、合约数量及成交额；全部一致，且 API 的合约换算也通过严格校验后，才替换成交量。任何冲突、缺失、未收盘或异常 API 响应均停止处理。
- 保留归档已有缺口，不添加 API 独有分钟，不填补平盘数据，不写死 SOL 合约面值。
- 修复后的 ZIP 只包含校验后的 CSV 和 `repair.json`，记录来源、原 ZIP 哈希及修复时间。校验后存入本地带哈希的缓存，后续无需重复逐页拉取。首次修复异常月包比普通下载耗时更久。

服务器业务代码没有修改；这次更新在桌面端完成。

## 验证

先用真实异常行编写回归测试：旧版本 8 个测试失败，报错与用户一致。实现后常规回归 7 个文件、43 个测试通过（另 1 个全月测试默认跳过）。其中包含原有 BTC 官方逐笔与分钟线对照、2023 年旧归档转换、缓存和 Binance 渠道隔离检查。

额外启用全月真实数据测试：使用已下载的官方原 ZIP 和独立采集的 API 响应，重放分页调用，通过生产修复函数处理；43,200 根分钟全部通过交叉核对，所有修复后的 SOL 成交量与 API 一致，合约单位为 1，得到完整 30 根日线。测试同时覆盖缓存复用、分页、归档缺口、价格/数量/成交额冲突、API 缺失、未收盘、换算异常和取消。
