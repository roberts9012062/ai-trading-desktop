# 行情逐笔时间与独立恢复

接口中心的 Tick 时间为 Unix 秒，可带毫秒小数；客户端转换为整数 Unix 毫秒保存到 `ts`，显示北京时间 `HH:mm:ss.SSS`。原来的秒级显示使同秒内不同成交全部看起来像 `08:03:01`，现在保留 `.123`、`.456` 等真实毫秒。真正同时发生的成交允许相同时间，以交易所成交 ID 区分，绝不伪造不同时间。

合并列表本来已经按 `ts` 降序排列，Collection 行情页直接按此顺序显示，去掉再次反转造成的旧成交排在前面。

逐笔成交使用自己的新鲜度，与报价、盘口和 K 线的存活状态分开。15 秒没有新鲜逐笔时，若 Key 有 ticks 权限，定时从接口中心取最近 100 笔并按成交 ID 合并。单次恢复完成前不重叠请求，失败尝试至少间隔 10 秒；退出或变更会话时停止。即使套餐连接数无法容纳逐笔 WS，首次快照和后续恢复也能独立工作。没有真实成交时不会生成假记录或改写旧成交时间。

2026-10-24 只读排查证据：授权服务器上两次公开 REST 最近成交时间从 00:05:31.045 UTC 继续推进至 00:05:34.789 UTC；独立公共 WS 的 8 秒观察收到 290 笔成交、60 个不同毫秒时间戳。未修改接口中心成交时间，也未更改测试 Key 的套餐或托管权限。

最终实际图表与成交列表验收通过：测试浏览器禁用 Collection WS，保守模拟套餐连接数为 3，REST 独立恢复取回持续更新的 100 笔成交，61 个不同毫秒时间，最新行时间推进至 `08:24:09.235`。截图和脱敏请求证据位于 `.local-data/collection-startup/`。该模拟仅修改测试浏览器读取的权限副本，没有修改真实 Key 权限。
