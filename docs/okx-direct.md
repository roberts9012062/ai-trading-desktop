# OKX 默认直连（v0.2.210）

用户要求：发行版行情和账户查询直接访问 OKX。开发电脑受限，VPN 只用于测试进程，
不把本机代理地址、VPN 配置或测试账户打包给用户。原有服务器登录、任务授权、
三端防重复和未知金融请求不重发的要求继续生效。

## 请求范围

| 功能 | 默认路径 |
| --- | --- |
| 60 个 USDT 线性永续合约及价格规格 | OKX `/api/v5/public/instruments` |
| 当前及历史 K 线、报价、最近成交、盘口 | OKX `/api/v5/market/*`，本机固定 GET 白名单 |
| 实时报价、盘口、逐笔成交 | `wss://ws.okx.com/ws/v5/public` |
| 实时各周期 K 线 | `wss://ws.okx.com/ws/v5/business` |
| 已同步账户的余额、持仓、挂单、历史委托、成交、账单、费用、收益 | Rust 持有凭证签名后直接 GET OKX |
| 尚未同步账户的兼容查询 | 业务服务器提供原签名，本机 GET OKX；不会把业务 JWT 送给 OKX |
| 私有账户与策略委托推送 | 生产 `ws.okx.com`、模拟 `wspap.okx.com` 的 private / business 通道 |
| 登录、创建任务、执行权、备用权益、金融写入和未知原单核对 | 保留原协调通道及持久化协议，未绕过执行权网关 |

行情及账户查询无需接口中心 Key。可选任务与备用服务配置仍保留在个人数据页。
已有未同步账户在业务服务器离线前须先同步凭证；直连不会凭空恢复缺失的账户密钥。
长期研究归档维持原独立数据来源，未把 Binance 归档伪称 OKX 数据。

## 实现与边界

`desktop-boot.ts` 开启统一桌面路由及 OKX provider，同时调用原生 `okx_enable_direct`。
默认 provider 的公共请求用 `okx_public_http`；只允许固定官方主机和公开 GET 路径，
禁止凭据、票据查询参数、跨主机 URL、路径跳转及重定向。不自动切回接口中心或旧
Snippet 节点。旧 provider 保留作兼容代码，发行版默认不启用它。

原生 `market_data::private_request` 在直连模式下只处理 GET，无须读取行情 Key。
签名、模拟标记及原查询保持一致；Secret 不随查询发送。`okx_signed_read` IPC 同样
拒绝 POST。`private_command` 的金融写入继续经原执行权网关，不能用直连 IPC 绕过
远端 fencing、原单登记和单次发送规则。正式生产交易与托管开关未改。

K 线单页最多 300 根，分页游标保持排除边界。原三天持久缓存、启动后台核对、
切换只更新最新尾部及 WS 缓存写入继续使用；共享缓存仍代表同一 OKX 合约及口径。
逐笔保留毫秒与 trade ID，最新在前。图表价格规格直接来自 OKX 合约资料；旧
`rb2610`、下市币种记忆迁移至有效加密合约，规格查询不因旧符号抛错导致整页空白。

## 验收

- 完整 App、隔离 Edge、合成业务身份、真实 OKX 数据：无接口中心 Key，60 个
  报价、12 个图表 canvas、盘口和 100 条逐笔成交；约 25 秒收到 2784 个真实帧。
  两次采样确认 K 线版本持续前进；两个 WS 均为 `ws.okx.com`，没有接口中心请求，
  也没有页面异常。数量显示另已修正浮点换算尾数溢出列的问题。
- Windows Rust 实际生产 HTTP 池：仅子进程注入 VPN 环境，17 个公共/模拟账户
  只读端点全部返回 OKX `code=0`。测试凭据由已有 DPAPI 保管库读入进程内存，
  不写进源码、参数列表或日志。
- 模拟 private / business WS：官方 `wspap.okx.com` 登录成功，account、positions、
  orders、orders-algo、algo-advance 全部确认订阅，心跳正常。
- 所有联调均为查询和订阅，没有下单、撤单、平仓、划转或真实权益变更。
- 全量前端 1337 通过、6 跳过；随后数量显示与传输的定向 21 项通过。Rust 库
  85 通过、5 显式忽略，真实 VPN 查询已单独显式运行。类型检查、生产前端构建、
  启动登录完整页面的 11 个断言通过，登录页联调同样没有页面异常。
- 原始证据保留于忽略目录 `.local-data/collection-connectivity/`。浏览器测试中的
  业务身份是隔离 fixture，不冒充真实服务器登录；原生网络与前端页面分别验收。
  正式安装包另由 Release CI 验证实际安装、覆盖升级和更新签名。

官方协议参考：[OKX V5 文档](https://www.okx.com/docs-v5/en/)。WS 使用当前官方
443 地址，不继续引入已公告停用的 8443 地址。
