# 启动统一缓存与图表切换

## v0.2.208 行为

桌面端配置好 API VALUE COLLECTION Key 并连接后，每次应用／Key 会话启动一个后台缓存作业。作业覆盖客户端现有的 60 个 OKX USDT 永续合约，以及 1m、5m、15m、30m、60m、240m、1d 七个周期，最多 420 项。断开重连、切换品种和切换周期不会重复启动整批作业；Key 或登录范围变化后旧作业停止。

历史缓存在本机 IndexedDB 的统一 `kline-history` store，使用 `collection-chart-v1` 来源命名空间，升级复用 v0.2.207 已有数据。缓存只保存公开 K 线，不保存 Key、票据或账户凭据。

后台作业按合约和周期逐项核对最近三个完整自然时长日加当前桶；长周期至少保留 240 根。1m 为 4,321 根，5m 为 865 根，15m 为 289 根。校验时间戳、来源、周期对齐、UTC+8 标签、OHLC 和成交量，移除损坏及重复数据，逐桶检查连续性，仅补缺口。新上市合约允许真实短历史，不伪造成交或平价 K 线。分页最多 500 根，采用 OKX `after` 排他游标，分批保存以便中断续补。慢下载跨桶后追赶最新尾部。

状态栏只显示“启动缓存 已完成/总数 · 后台补充历史”。后台历史使用普通 HTTP 排队优先级；当前图表尾部和账户查询先于下一页后台历史，连续紧急请求后仍给后台作业机会。

## 切换品种与周期

有内存或本地缓存时立即画出 K 线，不显示“正在核对”遮罩。只在后台请求最新尾部，通常两根；离开较久则按缺失尾部长度取最新一页，最多 500 根。不会因切换而重新扫描并下载历史内部缺口，深历史的核对与修复由启动作业处理。

尚无缓存的图表首次下载一次历史。后续切换复用本地数据。尾部更新失败时保留图表并显示轻量重试提示；无任何数据时才显示首次下载或错误界面。形成中的 K 线保持实时更新，已确认收盘的流数据持续写回已有缓存并裁剪窗口。

首次完整缓存需要逐步下载，取决于网络和套餐限流，不要求用户等全部 420 项完成才能使用桌面。显式向左翻页仍使用原有历史分页，秒级小规模恢复保留原接口边界。磁盘不可用时仍可在线取数，但无法持久加速下次启动。

## 验证

`collection-chart-cache.test.ts` 验证完整校验器；`collection-chart-session.test.ts` 验证切换只取尾部、网络等待时可读本地、启动仅执行一次和单项失败继续。`collection-config.test.ts` 验证并发原生 Key 读取。

实际浏览器入口为 `scripts/verify-collection-startup.py`（兼容入口 `scripts/verify-collection-cache.py`），从环境变量 `COLLECTION_LIVE_KEY` 读取已授权公共行情 Key。预先启动两合约、两周期缓存，故意延迟随后网络响应 5 秒，验证切换期间本地 K 线先显示且没有核对遮罩；再验证毫秒逐笔时间、最新在前和连接数不足时独立 REST 恢复。测试只读公开行情；业务账户接口用空测试响应，不发送金融写操作。临时证据位于忽略目录 `.local-data/collection-startup/`。

2026-10-24 发布前实测：两合约四项启动缓存完成且失败数为零；故意延迟数据响应时缓存品种切换 0.156 秒，切换历史请求为最新 2～3 根且没有历史游标。禁用测试浏览器的 Collection WS 后，REST 恢复持续推进成交时间，100 笔有 61 个不同毫秒时刻，页面异常为零。69 项定向回归、类型检查、生产前端构建通过。预览环境单次耗时不作为所有机器速度承诺。
