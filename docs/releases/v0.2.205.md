# v0.2.205 · 修复挂单与持仓查询排队超时

修复 v0.2.204 的 `接口中心响应超时 (code=COLLECTION_UNAVAILABLE)`：多个工作台账户请求同时签名，再进入与历史 K 线共用的串行 HTTP 队列，导致后面的请求在真正发送前就耗尽 11 秒响应时间。

改为先预留 HTTP 时隙，再向业务服务请求签名和发起查询。一个业务查询需要访问多个交易所端点时，按顺序复用预留时隙。账户操作优先于后续历史分页，每连续处理 4 个优先请求后给等待中的历史请求一次机会，避免 K 线持续等待。HTTP 并发仍保持为 1；写请求不自动重发；排队时切换登录或数据 Key 会取消旧请求。

验证覆盖：12 秒历史阻塞、8 个并发账户查询、单次业务查询的多个签名端点、历史公平调度和账号切换取消。浏览器联调注入 12 秒历史阻塞和每次 2 秒的网关延迟，工作台账户、持仓、成交、收益与交易所测试连通均成功，8 个额外并发查询全部返回成功，网关最大 HTTP 并发为 1。测试仍使用隔离示例账户，不代表调用方真实 OKX 凭证已经验收。

前端全量回归 1187 项通过（6 项跳过），TypeScript 检查与生产构建通过。线上真实测试 Key 验证票据与公开时间透传成功，观测总耗时约 3 秒；接口中心无需部署变更。
