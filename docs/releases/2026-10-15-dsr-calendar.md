# v0.2.196：因子挖掘 DSR 日历对齐

增强挖掘在特征有预热前缀时，因子序列会从统一的 `head_trim` 开始计分。
原生 GPU 精算却把裁剪后的因子长度与完整训练段比较，抛出
`CPU DSR factor/close calendar mismatch`；CPU 精算也会因收盘价未同步裁剪而广播失败。

两条路径现在都在 `[head_trim, train_end)` 上计算 DSR，与训练适应度和行为去重一致。
计分区间的初始仓位仍为零，首笔费用照常扣除，末根下一期收益仍为零。
真正的异常长度仍抛错，不跳过 DSR，也不改用未对齐的历史数据。

桌面版本为 0.2.196，原生引擎为 `native-gpu-v1-m3.9-dsr-calendar`，
CPU 内核为 `pykernel-factor-2026-10-15.1`。安装更新后，请新建挖掘任务；
旧任务已有版本校验，不能混用新旧评分。

验证覆盖 CPU 普通/短线精算、默认全选特征、原生增强挖掘中间代/最终代、
不同预热长度的手工 DSR 对拍、短线最终封存段、异常长度保护及报告缓存。
发布流水线增加 CPU DSR 回归检查；原生 CUDA 回归在本机执行。

旧版档案对拍测试显式固定 `crypto_ohlcv_v1`，避免原生引擎自动升级默认档案后
与 CPU 旧版档案比较；短线特征数断言改为使用实际基础和短线特征目录。

本次修改在桌面本地挖掘内核，服务器代码无需变更。
