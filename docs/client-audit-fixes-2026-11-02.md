# 客户端检查修复记录：v0.2.214

对应原始报告：[v0.2.213 检查报告](client-audit-2026-11-02.md)。原报告保留当时的缺陷证据，不覆盖历史结果。

## 本轮修复

1. **服务器账户下单防重**：客户端在发送前检查 `/api/live/order-requests/capabilities` 的协议 1 和账户指纹，落盘请求编号后只发送一次。响应丢失后，重复点击和“核对上次下单”只发 GET 原单核对，不再次发送金融 POST。并发点击、准备过程中切换线路、参数变化、磁盘写入失败、账户切换及无效成功响应均停止后续发单。旧服务无协议时不会发送订单。
2. **配套服务器实现**：私有业务代码新增 `server_order_requests`，用户与请求号组成数据库唯一门；稳定的交易所客户端订单号在任何金融 IO 前提交，成功结果与订单镜像一起提交。进程退出、超时、账户轮换或交易所查不到订单不能成为重发依据。只在确证金融 IO 前失败时标记 `not_sent`。该协议目前仅 OKX；旧版无请求号的网页 API 兼容路径保留，桌面所有服务器发单路径均使用协议 1。
3. **真实资产指标**：来源缺失的今日盈亏、风险率、余额、持仓占用和冻结保证金不再使用估算替代；界面展示缺失状态。本机真实余额取 `cashBal`、挂单冻结保证金取 `ordFrozen`，保留显式零；不把包含挂单的初始保证金需求 `imr` 当作持仓占用。接口字段口径参见 [OKX 官方账户文档](https://www.okx.com/docs-v5/en/#trading-account-rest-api-get-balance)。业务适配器也修正 `availEq=0` 被错误回退为 `availBal` 的问题。
4. **K 线完整性**：长断线尾部按保留窗口分页补齐，不再受 500 根截断；只有检测到实际内部缺口时调用缺口修复，正常切换保持本地读取与尾部刷新。新增 600 分钟断线和中部缺口回归。启动任务优先可见图表，不提高套餐并发或重启全量预热。
5. **启动与文案**：路由按需加载；主入口从 2778.94 kB（gzip 851.96）降至 695.60 kB（gzip 227.41），其他页面分块按需加载。账户来源文案区分服务器与单机。
6. **依赖与内容策略**：删除未使用 Zod；Vite 6.4.5、Vitest 4.1.12 及 source-map-js 修复版本入锁。官方 npm 全依赖审计为 0。生产 CSP 限制脚本为本机来源并阻止未授权内联脚本，保留 IPC、可配置业务/AI 服务、WebSocket、字体、音频和 Worker。`unsafe-eval` 与 WebAssembly 例外用于内置 Pyodide/Emscripten，不能宣称已全面禁用动态求值。策略参考 [Tauri 官方 CSP 文档](https://v2.tauri.app/security/csp/)。

## 后续加固建议

多账号长期刷新令牌仍沿用现有存储，需要单独完成加密保险库迁移和账号/离线恢复回归；可配置业务、研究和 AI 服务仍需较广网络目标权限，后续可改为按服务授权。CSP 中内置运行时的动态求值例外也需要升级或隔离运行时后再收紧。这些建议没有被标记为已解决，也不等于已证明存在可利用的远程入侵路径。
