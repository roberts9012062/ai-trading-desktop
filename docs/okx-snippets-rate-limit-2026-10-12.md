# v0.2.179：Snippets 历史校验限流与分页恢复

用户反馈 SOL 2024-04 官方归档修复仍报「Snippet 行情暂不可用」。这次不是代理 URL 或合约成交量校验出错：实际请求返回 HTTP 429，OKX `code=50011`、`msg=Too Many Requests`，响应头 `X-OKX-Upstream-Status: 429` 表明是 OKX 上游限流。

[OKX 官方文档](https://app.okx.com/docs-v5/en/#order-book-trading-market-data-get-candlesticks-history)说明历史 K 线按 IP 限速，50011 表示达到限速。Cloudflare 的公网出口由多个请求共享，客户端单个任务低于限速也可能收到 50011。

## 实际观察

- 从生产 Redis 只读确认线路池启用了 3 条 REST 线路：默认 kins、aeeu、zdds。
- 同一个 SOL 2024-04 请求：默认线路返回 429/50011，另外两条返回 code=0、100 根已收盘分钟线。
- 连续分页时也观察到三条线路都出现 50011。因此切换能利用健康线路，但不能保证上游持续放行。
- 本机连接 Snippets 与诊断会话的网络代理出口落在不同 Cloudflare POP；两种路径均实际出现过正常响应和 50011。
- 成功响应头有 `X-Snippet-Cache: PUT-ERROR`，本次不假设代理已缓存成功。
- 连续联网验收还遇到 HTTP 429 的纯文本 `error code: 1015` 响应，不能假设每个限流响应都是 OKX JSON；新增回归后也保留 HTTP 状态并按限流处理。

## 修复

1. 公共 REST 错误携带 HTTP 状态、OKX 错误码、可重试标记和 Retry-After；冷却按实际 origin 保存，受限线路不会阻止另一条健康线路。
2. 历史校验遇到 429/50011 或 HTTP 5xx 时，只从已认证服务器线路池请求新的可信 REST 分配。同一用户暂时避开受限线路，不把它上报成全局坏节点。无替代线路时恢复可信分配并等待冷却。
3. 每页最多 4 次尝试；尊重 Retry-After（至少现有 60 秒限流冷却），支持立即取消。所有节点持续不可用时明确提示「历史数据校验暂不可用」及 429/50011，不再误报归档文件校验失败。
4. 完成严格交叉验证的分页以独立键和 SHA-256 保存到现有本地缓存，计入 256 MiB 预算。中断后重新检查已保存分页，只请求未完成页；没有完整通过的归档不会进入研究数据缓存。
5. 原有 OHLC、合约数量、成交额、成交量换算、收盘确认及缺口检查继续执行。账户/交易请求逻辑不变。
