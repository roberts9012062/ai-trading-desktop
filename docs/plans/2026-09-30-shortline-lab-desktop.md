## 0. 任务与边界

在因子实验室一级菜单下新增**短线因子实验室**全新页面：短线因子挖掘（1m/5m/15m）+ 流式打分预览 + 组合 + 挂载服务器执行。

红线：
- **不动**已冻结的数值口径与合格门：cpu/gpu/native 引擎、crypto_local_v2/ohlcv_v1 研究契约、现有页面全部不改
- 涉及原生引擎源码（engine/*.py、VERSION）的改动必须：版本 bump → G1/G2/IR 重冻结（沿用 native-gpu 验收纪律）
- 挂载服务器的公式**只能使用"服务器可计算特征白名单"**（契约 §9），白名单外特征标记"仅本地研究"

## 1. 页面与路由

- 新路由 `/factor-lab/shortline`，一级菜单"因子实验室"下新增入口"短线因子实验室"
- 页面结构：挖掘表单（品种/周期 1m|5m|15m/种群/代数/成本/cadence）→ 进度卡（复用现进度组件风格）→ **实时分数预览面板**（冠军分+组合分曲线、最近 50 步环形缓冲、陈旧标记）→ 冠军表（新增翻转率/半衰期/打分稳定性列）→ "挂载到服务器"按钮

## 2. 数据层：aggTrades 回填与冻结（M-D1）

- Binance Vision 每日 aggTrades 归档下载 → 本地存储（断点续传、按日 SHA 清单）→ 按挖掘周期聚合成窗口统计
- 冻结协议：数据集 = 日快照 + 修正记录；dataset SHA 进任务元数据，保证重跑逐位一致
- 磁盘预算：先单品种（ETHUSDT）2 年；展示占用与清理入口

## 3. 特征批次 v4（短线专属 token，M-D2）

每窗口（来自 aggTrades）8 个订单流统计量进表达式语言，token id 使用 ≥104 本地专属区间：
订单流失衡（主动买占比 z）、大单占比、成交强度 z、量价分歧（方向反转频率）、VWAP 偏离、爆发比、强单连击、节奏熵。引擎版本 bump + G1/G2 重冻结；特征按"服务器白名单内/仅本地"双标记。

## 4. 挖掘引擎改动（不动现有引擎，新短线 profile）

- 挖掘仍在**收盘 K 线**上训练（复用原生引擎 f64 权威管线）
- fitness 新增：**换手正则**（换手惩罚直接进选择压力）+ 翻转率/半衰期惩罚
- 短线合格门（新 profile `shortline_v1`，与现有门并列不共享）：打分稳定性（窗口内分数方差）、翻转率上限、**采样点 IC**（tick 重放在 cadence 时刻对后续 K 分钟收益）、执行延迟鲁棒性（延迟 3–10s 的衰减）、封存段揭示沿用现有机制

## 5. Tick 重放验证器（M-D1 核心）

- 输入冻结 aggTrades 数据集 + cadence → 逐时刻重建形成中 K 线（含量时间归一，规则与服务器契约逐字段一致）→ 逐冠军+组合打分 → 分数流
- **确定性**：同数据集+同 cadence 双跑逐位一致（验收门 D1）；重放器代码即未来实盘打分代码（同一实现两处使用，禁止两套）

## 6. 流式打分预览（M-D3）

- 订阅 Binance WS aggTrade，用与重放器**同一套**形成中 K 线构造代码，按 cadence 增量打分
- 冠军分 + 组合分（复用 GPU portfolio 冻结 IC 权重）实时曲线；50 步环形缓冲；断线 → 分数标"过期"置灰
- 纯 UI 预览，不下单

## 7. 挂载到服务器（M-D4）

- 按契约 §9 组装任务载荷（白名单特征校验、权重归一、决策默认参数）
- **导出黄金夹具**：`{tick 流样本, forming bar 规格, cadence, 公式集, 期望分数序列}` + manifest SHA，挂载时随任务提交，服务器 S1 门用它做逐位校验
- 挂载后任务状态轮询/展示（分数 50 步、持仓、决策流）

## 8. 验收门

- **D1**：重放器双跑逐位一致（多数据集×多 cadence×多公式）
- **D2**：短线 profile 挖掘全链路跑通；合格门按新指标正确拒绝/通过（0 合法）
- **D3**：流式预览与重放器在同一 tick 序列上分数一致（实时=回放）
- **D4**：挂载载荷通过服务器 S1 夹具校验（与服务器 AI 联调）
- 全量 Vitest 绿；原生引擎改动完成 G1/G2 重冻结后才可提交

## 9. 分期

M-D1 数据管道+重放器（D1）→ M-D2 v4 特征+fitness+短线门（D2）→ M-D3 页面+流式预览（D3）→ M-D4 挂载+夹具出口（D4，与服务器 M-S1 联调）
