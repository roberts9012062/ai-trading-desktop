# 单机模式优先使用已配置的接口中心

用户要求：单机模式保存 API VALUE COLLECTION Key 后，使用接口中心线路。
没有 Key 或用户显式清除后使用 OKX 官方直连。无需再增加网络模式开关。

路由统一覆盖合约资料、K 线与三天缓存补齐、报价、盘口、逐笔、公开 WS、
账户余额、持仓、挂单、历史委托、成交、账单、收益分析及私有 WS。
配置按桌面账号隔离。Key 加载中、不可解密、权限失效或中心断线均不能临时
切到 OKX；显示错误并等待用户处理。金融写入、执行权观察、未知原单核对、
服务器登录和任务授权保持原有协调通道。

实现使用共享 provider 判断配置状态。前端在选择线路前等候配置读取；公共
WS 由稳定的订阅对象切换底层连接，保留订阅并过滤旧回调。原生普通查询每次
检查当前 scope 的密封 Key 文件，存在则走原中心签票通道，即使文件损坏。
断开的旧 Collection 对象不应因配置通知自行复活。

验收包括配置/清除/损坏/切换账号、中心失败无直连回退、两向 WS 切换、
原生 scoped Key 优先级、真实公共行情与模拟账户只读查询，以及发布流水线
对更新签名、实际安装与升级的检查。任何联调都不发送金融写入。

## 本地验收

- 最终全量前端：1348 通过、6 条件跳过；类型检查与生产构建通过。
- Rust 库：87 通过、6 显式忽略；其中新的真实中心只读联调另行显式执行成功。
- 完整 App 使用隔离合成业务身份、真实 OKX 与中心公共行情：未配置时连接
  官方 OKX，保存 Key 后旧连接全部关闭、中心三条公共 WS 持续更新，显示 60
  报价、100 笔成交、盘口与 12 个图表 canvas；两次采样确认 K 线版本前进。
  配置阶段没有新的 OKX 直连请求，显式清除后恢复官方连接，没有页面异常。
- 原生实际 HTTP 池经中心签票转发：模拟账户余额、持仓、挂单三项均返回
  OKX code=0。凭据只在测试进程内存中加载，不进入参数、源码和日志。
- 检查了未完成合约请求与新配置竞争：新线路发起独立请求，旧响应被取消，
  不会将旧线路请求共享给当前配置。
- 原始证据位于忽略目录 `.local-data/market-provider/` 及
  `.local-data/collection-connectivity/provider-*.log`。安装包发布验收另行记录。
